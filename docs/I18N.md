# GitVerse — Internationalization & Localization (`i18n`)

## 1. Supported Locales

| Code | Name | Language | Direction | File |
|---|---|---|---|---|
| `en` | English | `en-US` | LTR | `i18n/locales/en.json` |
| `fa` | فارسی | `fa-IR` | RTL | `i18n/locales/fa.json` |

## 2. Parity & Validation Rules

1. **Zero Hardcoded Strings**: All user-facing labels, headings, tooltips, dialogs, and error messages must use `$t('...')`.
2. **Key Parity**: Every key present in `en.json` must be present in `fa.json` and vice-versa.
3. **Placeholder Matching**: Placeholders like `{branch}` or `{count}` must match exactly across all locales.
4. **Validation Command**: Run `node scripts/validate-i18n.mjs` (or `npm run validate:i18n`). CI fails if any key is missing or mismatched.
5. **RTL Formatting**: Use CSS logical properties (`ms-*`, `me-*`, `ps-*`, `pe-*`, `start-*`, `end-*`, `text-start`, `text-end`). Technical values (hashes, Git refs, branch names, file paths) retain `dir="ltr"` and `font-mono`.
